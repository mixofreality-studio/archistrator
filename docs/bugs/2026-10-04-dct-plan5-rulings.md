# DCT Plan 5 — architect rulings per round

System-architect rulings on every red item a Plan 5 round reported, under the founder's
standing principles for this wave, in priority order:

1. every API has a use case (add the use case / dynamic-view call, or delete the op);
2. fix it right, never weaken a gate (no waivers, `//nolint`, lint-config exemptions, `t.Skip`);
3. breaking changes are fine — delete, don't deprecate — and every schema change conforms
   archistrator's own `project.json` in the same change;
4. tests are only generated black-box scenarios on the real stack;
5. the spec §11 (Amendment A) and §12 (Amendment B) rulings stand.

"Done" rows name the commit on `deterministic-component-testing` (merged `--no-ff` from
`dct5r1-arch`). "Ruled" rows are settled by a principle and handed to the named unit or
binder of the next round, with the decision they must implement. "Escalated" rows are
listed in the round's structured result: no principle settles them, or carrying them out
needs a permission this session does not hold.
